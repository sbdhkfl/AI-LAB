# AI-LAB Beginner Mode

AI-LAB is designed so a person can build a project without already being a programmer, Linux expert, electronics expert, or AI engineer.

## The golden rule

**Never make the user guess the next move.**

Every generated project should answer four questions at every step:

1. What do I do?
2. What should I see?
3. What if I do not see it?
4. Should I stop before continuing?

## Standard project format

### 1. What are we building?
Use short, plain-English explanations. Explain difficult words the first time they appear.

### 2. What do I need?
List hardware, software, cables, genuinely required accounts, approximate resource needs, and files the project creates. Separate required items from optional upgrades.

### 3. Before we start
Give a short checklist. For hardware, include power and wiring checks. For software, include OS, runtime version, and storage checks.

### 4. Build it one step at a time
Every step should contain:
- Step number
- Simple title
- Do this
- Copy/paste command or exact action when possible
- You should see
- If it does not work
- STOP HERE when continuing could make a problem harder to diagnose

### 5. Test after each major stage
Do not wait until the end to discover that an earlier step failed.

### 6. Debugging
Never tell a beginner only "check the logs." Give the symptom, likely cause, safest first fix, and verification step.

### 7. Complete code
Prefer complete files over scattered snippets. Generated code is not silently executed; the user gets a review/test checkpoint first.

### 8. Final checklist
Every project ends with installation, detection, main-feature, error-handling, configuration, secret-handling, and ready-to-use checks.

## Two learning levels

- **Beginner Mode:** maximum explanation, one step at a time, common-error fixes, and simple vocabulary.
- **Advanced Mode:** shorter instructions, architecture details, APIs, optimization notes, and developer-oriented diagnostics.

Both modes use the same underlying project specification.
